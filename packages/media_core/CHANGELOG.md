## Unreleased

- A `job` module for how a background job ends: `MediaJobOutcome` (kind, the label a viewer would recognise, the job's own verdict, bytes, elapsed, error), `MediaJobReporter`, and the `MediaJobReporting.reporter` slot. `media_core_download` and `media_core_recording_ffmpeg` report finished and failed work through it, and `media_core_notify` registers itself there when a host enables it — which is what lets a job say how it ended without either job package depending on a notification plugin, and lets a host that draws its own progress install something else or nothing at all. It is the same split `PlayerKernel.audioDriverFactory` uses for the system media surfaces.

- **This package's public API changed shape, and its docs are complete**: `very_good_analysis` with `public_member_api_docs` is now satisfied with no rule disabled, which meant the two approved API changes. Boolean parameters are named — `setMute(muted:)`, `setLoop(loop:)`, `setAudioOnly(audioOnly:)` on `PlayerHandle` and the `PlayerAdapter` contract, the fifteen `PlayerConfig`/`PlayerOptions` `withX(value:)` builders, `PlayerCoreState.withSource(value:)` and its siblings, `SessionController`/`PlaybackController.setBuffering(buffering:)`, `PlaybackCommand.buffering(value:)`, `PlaybackRequest.buffering(value:, source:)`, `RendererController.setSurfaceReady(value:)`, `VisibilityController.setViewport(value:)`/`setOccluded(value:)`, `FullscreenWindow.setFullscreen(value:)`, `AudioManager.setEnabled(value:)`. Assignment-only methods became documented fields: `PlayerKernel.platformProvider`, `PlayerKernel.presentationDriver` (the `attachPlatformProvider`/`attachPresentation` methods are gone; `detach…` stay, they do more than assign), `PlayerHandle.recoveryEnabled`, `PlayerHandle.engineFallbackEnabled`, `PlayerHandle.playIntent`, `PlayerSession.errorMessage`, `QualitySwitchController.current`, `ThermalManager.state`. `PlayerAdapterBase.emitBuffering` takes `{required bool buffering, resumePlaying, progress}` and its `onSetAudioOnly` hook is named too, so every adapter subclass in every backend package was updated with it. Static `parse`/`fromValue`/`fromJson` helpers on the identity, task, operation and media-type value types are named constructors now, which leaves their call syntax alone. `avoid_returning_this` removed `PlayerSlot`'s fluent returns. Roughly 1,200 doc comments were added, each saying what a member is for rather than restating its name, and the async findings that were real (`discarded_futures` on a session's event fan-out, a `cancel_subscriptions` that was already handled through a local copy) were resolved with the reason written next to them.


- The app going to the background now reaches the players. `AppLifecycleDriver` has existed in this package since the beginning and nothing anywhere constructed it, so a video kept decoding with the app hidden and a "background playback off" switch had nothing to switch. `PlayerKernel` now registers itself as a lifecycle observer (when `KernelOptions.pauseWhenBackgrounded`, which is on by default) and deactivates **every** handle it owns that is actually playing — a wall, a feed's warm window and the visible player all stop, because "nobody can see it" and "nine decoders are running" was never a choice anyone made. Returning to the foreground does not press play. A single player can be exempted with `PlayerConfig(pauseWhenBackgrounded: false)`, which is what a narration or podcast track passes; a whole app opts out through the kernel option. `dispose()` drops the registration, and a process without a Flutter binding gets no observer instead of throwing.
- Recovery now waits between its attempts. `KernelOptions.retryBaseDelay` and `retryMaxDelay` documented a retry backoff that **nothing read**: `RecoveryLadder` ran reopen → next line → next engine back to back, so an engine that had just refused an open was asked again in the same millisecond, and a source that is gone for real is hammered for as long as the sweep has rungs left. The ladder takes a `retryDelay` resolver (null keeps the old immediate escalation, which is what a bare `RecoveryLadder` still gets); `PlayerHandle` passes one built from the two options, attempt 1 stays immediate because the failure that opened the sweep already cost the viewer the time one retry is worth, and a step whose wait was overtaken by a new open or a close does not run at all. The documented "back off linearly" became what the code actually does — doubling with jitter through the core's `RetryUtils.backoff`, the same shape the recording restarts use, so a feed whose players all fail on one dead CDN do not re-ask it in step.
- Playback: a volume or rate request no longer cancels the operation that was already running. Both went through the same single cancellation slot as `play`/`seek`, so touching the slider while the engine was still answering a `play` cancelled that continuation — the play never reached the engine, and the viewer saw a button that did nothing. The slider drags are now coalesced by request number instead (the newest value applies, the intermediates are dropped before the round trip), which keeps the whole drag down to one engine call while leaving `play`/`pause`/`seek` free to supersede each other as before.
- Testing: `FakePlayerAdapter.gate` holds a named engine call until the test releases it, so "while X was still in flight" is finally something a suite can express.

- Casting: `CastController`'s position ticker no longer overlaps itself. `refresh()` is a network round trip to the receiver, and the previous body fired `unawaited(refresh())` on every tick, so a slow or wedged renderer accumulated one in-flight request per tick - and a late answer could overwrite a newer reading. A tick is now skipped while the previous poll is still waiting.
- Playback pool: an item **replaced behind the same index** is now re-opened instead of resumed. `setItems` shifted the list but `_ensureActive` compared only the index, so after a refresh the held player kept playing the video that used to sit there; assignments now remember the source they were opened on and re-point when it differs.
- Testing: `FakePlayerAdapter.emitPosition` reports a position the way an engine's position stream does, so a UI can be tested against tick frequency.
- `OperationContext.withoutX()` now clears the field it names. All fifteen helpers — `withoutPlayerId()`, `withoutUri()`, `withoutReason()` and the rest — were `copyWith()` with no arguments, and `copyWith` reads an omitted argument as "keep what is there", so each one returned a copy identical to the receiver while its own doc comment promised the field was gone. A caller that wanted a context stripped of its player identity got the identity back, which is what a log line, an error report or a reused operation ends up carrying. Clearing is now what `cleared({playerId: true, …})` asks for, field by field, and every helper is one call to it; the omitted-means-keep behaviour of `copyWith` stays, because building a context needs it.
- `PresentationPolicy` compares all ten of its fields. `operator ==` and `hashCode` listed nine and left out `allowWindowFullscreen`, the switch that says whether "fill the window" is on offer, so a policy that forbade it compared equal to one that allowed it and had the same hash — anywhere the two were treated as one value (a cache key, `==` on a rebuilt widget, a "did this change" guard) the restriction was silently dropped. `test/operation` and `test/policy` now hold the regression tests for both, each one walking every field so the next one added cannot be left out the same way.

## 0.1.0

Initial release.

- Identity and generations: `SourceId` / `SessionId` / `GenerationId` / `OperationId` value objects; the generation is what lets late events from a previous playback attempt be dropped.
- Sessions and handles: `PlayerSession`, `SessionController` and `PlayerHandle` — the handle is the host-facing facade, mirroring playback state and the declared playback intent.
- Command serialization: task queue (`ExclusiveTask` / `KeyedAsyncLock`), state machine and reconciler, so commands on one player never overlap.
- Recovery: a single `RecoveryLadder` decision (switch line / switch engine / rebuild), failure classification and snapshots; recovery restores play or pause from the declared intent.
- Events: a normalized playback event bus (`PlayerEventBus`) with priorities and pluggable event filters.
- Player pool and preload: pooled reuse, the preload manager and resource reclaim policies.
- Observation and diagnostics: `OperationTracker` (operation history), the diagnostics manager and debug snapshots.
- Resources: the memory accounting bridge, resource manager and memory pressure response.
- Platform and network: platform provider abstraction, network monitoring and cache policies.
- Adapter contract: `PlayerAdapter`, `PlayerVideo`, the adapter registry and the capability / priority based selector; engine-independent video geometry (`VideoOrientation`).
- Also: screenshots (multi-route capture plus a writer), the recording and casting contracts, error and result types. (The FLV rewriting and loopback relay live in `media_core_ingest`, not here.)
