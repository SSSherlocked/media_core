# Changelog

Changes to this project (the `media_core` workspace), newest first. Every package keeps its own `CHANGELOG.md`.

## Unreleased

- **The whole workspace is lint-clean, and public APIs paid for it**: the shared `analysis_options.yaml` now runs `very_good_analysis` with `public_member_api_docs` on, and every one of the ~2,300 findings is gone — no rule was switched off to get there. Two groups of the fixes changed signatures, which the owner approved over disabling the rules: a positional `bool` parameter became a named one (`handle.setMute(muted: true)`, `setLoop(loop:)`, `setAudioOnly(audioOnly:)`, `PlayerConfig.withMuted(value:)` and its builder family, `PlaybackCommand.buffering(value:)`, `RendererController.setSurfaceReady(value:)`, `VisibilityController.setViewport(value:)`, `DanmakuOverlaySession.setEnabled(enabled:)`, `DebugUtils.assertDebug(condition:, message:)`, `ValidationUtils.ensure(condition:, message:)`, and the same inside every package that had one), and a method whose only job was to assign a field became a documented public mutable field (`PlayerKernel.presentationDriver = driver` instead of `attachPresentation(driver)`, `PlayerKernel.platformProvider`, `PlayerHandle.recoveryEnabled` / `engineFallbackEnabled` / `playIntent`, `PlayerSession.errorMessage`, `QualitySwitchController.current`, `ThermalManager.state`, `FakePlatformProvider.type` / `info` / `capabilities` / `device` / `codecs`). Static `parse`/`fromValue`/`fromJson` helpers became named constructors — call sites unchanged. `avoid_returning_this` cost `PlayerSlot` its fluent chaining (nothing chained on it), `@immutable` states what the value types already promised, and `discarded_futures`/`cancel_subscriptions`/`avoid_slow_async_io` findings were checked one by one as possible bugs rather than swept: the honest awaits and cancels were added, and the places where awaiting would have changed ordering are documented in place instead of "fixed". Dependency keys are alphabetical in every `pubspec.yaml`.

- **Engine configuration belongs to the caller, verbatim**: the adapter-owned config wrappers are gone — `MediaKitPlayerConfig`/`MediaKitVideoConfig`, `FvpPlayerConfig` and `FijkPlayerConfig` are deleted; `MediaKitPlayerAdapter` now takes media_kit's own `PlayerConfiguration` + `VideoControllerConfiguration`, fvp takes a raw mdk `properties` map plus native `videoDecoders`/`audioBackends` lists, ijk takes a raw `EngineOption` list applied before every open, and better_player takes the native `BetterPlayerConfiguration`/`BetterPlayerPlaylistConfiguration`/`BetterPlayerDataSource` directly. The adapter also stopped deciding anything on the host's behalf: fvp's seven auto-applied live properties and the legacy-HEVC-FLV software-decode rule (and its default host list) are removed — a host that needs them passes the properties or decoder order itself; ijk's `enableCodec`-derived option block and default `reconnect`/`timeout`/`fflags` are gone the same way, and media_kit lost its last auto value (`enableRtxVsr`'s filter chain).
- **Runtime engine options, with automatic rebuild**: new `EngineOption` contract (`applyEngineOptions` on `PlayerHandle` and every adapter, plus the `supportsEngineOptions` capability). Options are persisted by the handle and replayed on every fresh engine — recovery swaps, fallback, rebuilds. Each option reports what happened (`appliedLive` / `stagedForNextOpen` / `needsRebuild` / `unsupported`); with the default `immediate` effect an option the running engine cannot take live triggers a same-backend engine rebuild that preserves the open source, position, volume, rate and play intent. `PlayerHandle.rebuildEngine()` is public for the same purpose. Engines without a live key/value surface (better_player) answer honestly and rebuild; ijkplayer options are accepted by the live instance but honestly reported as staged (consumed at the next open).
- **Composed names for media_core's own public types**: the four bare names that collided with the re-exported engines are gone — `Player` → `PlayerIdentity` (the identity value object), `PlayerState` → `PlayerCoreState`, `PlaybackState` → `PlayerTransportState` (the transport mirror) and `MediaType` → `PlayerMediaType` (symmetric with `SourceMediaType`). With that, the adapter barrels re-export their engines **without any `hide`**: a host importing both barrels gets media_kit's `Player`/`PlayerState` and mdk's `PlaybackState`/`MediaType` unambiguously, and `audio_service`'s `PlaybackState` is nameable bare inside `media_core_mediasession`. `player_state.dart` split into `player_core_state.dart` + `player_lifecycle_state.dart` + `player_playback_state.dart`; files renamed to match their primary class (`flv_lzc_player_adapter`, `live_source_request`, `audio_playback_state`, `memory_log_sink`, `player_video`); the ijk factory class is `FlvLzcPlayerAdapterFactory` to match its adapter's prefix.
- **God files split by concern**: `PlayerHandle` (2700 lines) now keeps constructor, fields, the `RecoveryTarget` overrides and `dispose` in `kernel/player_handle.dart` and moves the rest to five `part` files (operations / playback / lifecycle / recovery / adapter bridge) — public extension groups, so every existing call site compiles unchanged (only narrow `show` imports need the extension named, e.g. `PlayerHandlePlayback`). Same treatment for `TaskManager` (execution / cancellation parts, exceptions in `task_errors.dart`), `MultiviewController` (value types in `multiview_snapshot.dart`; cells / focus / internals parts), `LivePlaybackController` (sweep / pipeline parts), `LiveWatchdogs` (the four watchdog arms in `live_watchdog_arms.dart`) and `MediaKitPlayerAdapter` (engine configuration part). `AudioPlaybackConfig` moved to its own file and `bette_player_adapter.dart` is finally spelled `better_player_adapter.dart`. The engine adapters' bare `debugPrint` calls now go through `MediaCoreLog` like every other module.
- **Dependencies**: `media_kit` and `media_kit_video` now resolve from `Predidit/media-kit` pinned at `803c4a27`, and `fvp` from pub.dev as `^0.38.1`. The copies that used to live in `packages/` are gone. The pinned revision does **not** contain the PureLive fork patches (`VideoController.setVideoOutputEnabled`, the Android Surface/`vid` ownership, the Windows `frameRevision` signal), so no package may call them.
- **Consequence for Android natives**: with the upstream bundles the bundled libmpv is back on FFmpeg 7.1, and the self-built FFmpeg 9 bundles are no longer shipped here; a stream that only a newer FFmpeg can read is the caller's problem now (see the next bullet).
- **Adapter re-exports**: every backend adapter re-exports the engine it is built on, so a host gets that engine's API from its single adapter dependency — `media_core_media_kit` (media_kit + media_kit_video; `Player` and `PlayerState` hidden), `media_core_fvp` (`fvp/mdk.dart` + `fvp/fvp.dart`; `Player`, `PlaybackState` and `MediaType` hidden), `media_core_better_player` (better_player_plus) and `media_core_ijk_player` (flv_lzc). Names are hidden only where `media_core` exports its own type of the same name.
- **No business logic in the packages**: the Douyu FLV continuation relay (URL leases and renewal) was removed from `media_core`'s source layer and from all four adapters, and now the legacy-HEVC FLV layer follows it out: `source/flv` (rewrite relay, tag rewriter, framer) is gone, `MediaKitPlayerConfig.legacyHevcFlvHosts` with it, and the media_kit adapter no longer reroutes any source — which sources a bundled FFmpeg cannot read is application knowledge, so a host that needs the rewrite runs its own relay. To make that work, a source URI on loopback is now exempt from the native proxy automatically (`media_kit` adapter), since a caller-owned relay must never be proxied. The fvp adapter keeps its decoder rule (legacy-HEVC hosts decode in software) — it does not reroute anything and its list stays caller configuration.

## 1.0.0

Initial release.

- **Core** (`media_core`): a platform-agnostic orchestration layer of 40 modules — identity and generations, sessions and handles, command serialization (task queue / state machine / reconciler), the recovery ladder with failure classification, player pool and preload, normalized events, operation tracking, memory and resource accounting, screenshots, diagnostics. It contains no platform code, UI or theming.
- **Four playback backends**: `media_kit`, `better_player` (video_player), `fvp` (libmdk) and `ijkplayer` (flv_lzc), all behind the adapter contract (`PlayerAdapter` + `PlayerVideo`), selected by capability and priority, and swappable at runtime.
- **Live** (`media_core_live`): line and engine sweep, stall watchdogs and backoff retry for non-seekable streams; single-use signed URLs are refreshed before an engine switch.
- **Presentation**: fullscreen (`media_core_fullscreen`) and picture-in-picture (`media_core_pip`), coordinated as one state by `media_core_presentation` with video-orientation awareness.
- **Player UI** (`media_core_ui`): one control layer (state / actions / theme tokens) plus six design languages (material, cupertino, fluent, macos, yaru, neumorphic), including pinch zoom and screenshot entry points.
- **System media surfaces** (`media_core_mediasession`): Android notification, iOS lock screen and control center, Windows SMTC and Linux MPRIS, plus audio focus, interruption handling and pause-on-unplug.
- **Content shapes**: vertical feed (`media_core_feed`), list playback with resume (`media_core_list_playback`), multiview live wall (`media_core_multiview`), danmaku (`media_core_danmaku`) and music playback (`media_core_audio` — sources, queue, play modes, lyrics and the desktop lyric windows, downloads).
- **Platform and infrastructure**: native capability probe and background execution (`media_core_native`), levelled logging (`media_core_logging`), memory accounting (`media_core_memory`), offline downloads (`media_core_download`) and FFmpeg recording (`media_core_recording_ffmpeg`).
- The vendored `media_kit` and `media_kit_video` follow their upstream versions with fork patches (Native Assets build, native event loop, renderer binding); the differences are listed in their own `CHANGELOG.md` files.
